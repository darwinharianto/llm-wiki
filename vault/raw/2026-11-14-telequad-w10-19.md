7.12.2.3	MT call handling When an MSP subscriber roams into a network not supporting CAMEL Phase 2, the default profile will be used for all outgoing traffic. 7.12.2.2	MO call handling The HLR will send the outgoing call barring data and outgoing ODB data, specific to the default profile, to the VLR. 7.12.2.1	Actions required on Location Update Other handling for this scenario is described in 3G TS 23.078. This subclause details MSP specific handling for roaming into a network not supporting CAMEL Phase 2. 7.12.2	Roaming into a network not supporting CAMEL Phase 2 The default profile subscription information shall apply to all supplementary services, excluding Call Forwarding and Call Barring, provisioned per profile. When roaming into a network not supporting CAMEL Phase 3, only the functionality of MSP Phase 1 will be available to an MSP subscriber. 7.12.1	Roaming into a network not supporting CAMEL Phase 3 7.12	Exceptional Procedures

Provision and Withdrawal of MSP Annex A (informative): If an MSP subscriber roams into a network not supporting the Network Indication of Alerting feature, or is using an MS that does not support the Network indication of Alerting feature, then the subscriber will still receive all MT calls, but no indication of the called profile will be given. 7.12.3	Lack of availability of the Network Indication of Alerting feature MO short messages will be sent from and charged to the default profile. 7.12.2.4	MO short message handling The HLR will not allow OR, this means that for MT calls, the GMSC will always support CAMEL Phase 2, allowing the gsmSCF to invoke appropriate Call Forwardings and Call Barrings. MT calls to any profile will be received by the subscriber (subject to call forwardings and call barrings provided in the gsmSCF on the called profile), although no indication of the called profile will be received.
